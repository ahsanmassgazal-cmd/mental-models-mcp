# 7 Mental Models for Better Decisions

Apply one (or a short chain) of these models to the user's real situation. Never just explain the framework. Work it through with their names, numbers and dates, and finish with **one decision + the first action in the next 24 hours**.

If the Mental Models MCP is connected, use its tools (`recommend_mental_model`, `apply_mental_model`, `decision_playbook`). Otherwise follow this file.

## Step 1: Pick the model

| Situation signal | Model |
|---|---|
| Urgent, competitor move, market shift, pivot | **1. OODA Loop** |
| New product, pricing, "too expensive", innovation, building from scratch | **2. First Principles** |
| Team/partner decision, brainstorm, conflict, evaluating a big idea | **3. Six Thinking Hats** |
| Too many tasks/clients/products, need focus, scaling, performance review | **4. 80/20 Principle** |
| Problem keeps recurring, failure, complaints, metric dropping | **5. Root Cause Analysis** |
| Many possible explanations, confusing data, overcomplicated strategy | **6. Occam's Razor** |
| Stress, rude person, rejection, overthinking | **7. 5x5 Rule** |

For big decisions, chain them: **5x5** (does this deserve deep thought?) → 1-2 core models → **OODA** (turn it into action and set a review date). Say in one line which model(s) you're using and why.

## Step 2: Apply it

**1. OODA Loop (John Boyd).** Observe: gather the facts. Orient: analyse context and bias. Decide: pick the best action, fast and reversible. Act: execute, then loop again.

**2. First Principles.** Identify the problem in one sentence. Break it into fundamental pieces. Challenge every assumption (law or just convention?). Rebuild from the truths that remain.

**3. Six Thinking Hats (Edward de Bono).** One mode at a time: ⚪ White data · 🔴 Red emotions · ⚫ Black caution · 🟡 Yellow positives · 🟢 Green creativity · 🔵 Blue process. Summarise under Blue and **end with a decision**.

**4. 80/20 Principle (Vilfredo Pareto).** List the tasks, clients, products or channels. Measure the outcome and cost of each. Find the 20% driving most results and double down. Eliminate, automate or delegate the rest (name each bucket).

**5. Root Cause Analysis (Sakichi Toyoda, 5 Whys).** Define the problem precisely. Ask "why?" about five times. Validate the root cause: if it's removed, does the problem stop? Fix the root, not the symptom. Gather data after the fix.

**6. Occam's Razor.** Define the problem. List every explanation. Pick the one with the fewest assumptions. Act on it; revisit only if evidence contradicts it.

**7. 5x5 Rule.** Pause before reacting. Ask: "Will this matter in 5 years? If not, don't spend more than 5 minutes on it." Act on one useful step. Reframe it as a lesson. Repeat daily.

## Step 3: Output

1. **Model(s) used:** one line on why.
2. **Walkthrough:** each step briefly, applied to the situation (use a table when comparing options).
3. ✅ **Decision:** one sentence.
4. **Next action (24h)**, **metric to watch** and **review date**.

## Pitfalls
- Explaining the model instead of applying it.
- Stopping Root Cause at the first "why" (that's a symptom).
- Calling "competitors do X" first principles (that's analogy).
- Ending Six Hats without a Blue-hat decision.
- Using 5x5 to dismiss things that genuinely matter long-term.
